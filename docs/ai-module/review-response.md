## Deferred, with reasoning

**Narrow `nest-patterns` to guard-order/module-ownership, or fold it into `quality-gate`.**
Not implemented. It found zero violations against this codebase (already true when the review
raised this), but that reflects the codebase having already been through one review pass, not
that the checks are worthless — a future PR that gets the DI/decorator/guard-order/circular-
dependency wiring wrong is exactly what it exists to catch, and none of those are enforced by
the compiler or NestJS's own bootstrap in every case (a reversed guard order, in particular,
runs without error — it's just wrong). The assignment specifically asked for a NestJS-patterns
skill distinct in purpose from `quality-gate`'s layer/money check; folding them would blur that.

**Add a 7th "duplication" row to `clean-code`'s checklist.** Not implemented, on purpose — the
audit's duplication findings (`toBoolean()`, the two email job-data interfaces, the low-stock
threshold) were all found by reading the diff/files directly, not by any mechanical rule a skill
row could cheaply encode (detecting "this logic already exists elsewhere" needs a repo-wide
search per candidate, which is a different cost profile than the other 6 checks). Left as a
manually-called-out bonus finding rather than a formal row until there's a cheap, reliable way to
check it. `audit-findings.md`'s wording was tightened to say so explicitly instead of "not yet."

One thing this _did_ change: an attempt to add `paths:` frontmatter to `nest-patterns` (scoping
when it auto-activates to controller/service/guard/module files, addressing the "ran on
everything, found nothing" complaint a different way) was tested live and reverted — it made the
skill entirely unresolvable ("Unknown skill" from the Skill tool) rather than just deprioritizing
it, the opposite of the intended effect. See `df8843d`'s commit message. `argument-hint` and
`allowed-tools` were kept; only `paths` was dropped.

## Notes on skill-design fields, verified live

- `disable-model-invocation: true` (on `docs-sync`, `clean-code`) doesn't just suppress automatic
  triggering — it blocks the Skill tool from invoking it at all, for any reason, including a
  direct request from the developer to Claude ("run docs-sync for me"). Only literally typing
  `/docs-sync` yourself works from here on. This matches the review's own stated intent
  ("workflows with side effects... you want to control timing") but is worth knowing explicitly:
  it's a stricter gate than "don't auto-trigger."
- `context: fork` on `quality-gate` works as expected — its build/lint/test/e2e output runs in a
  forked subagent and only a condensed report returns to the main conversation.
